---
title: Capabilities
description: Configure web search and web fetch, choose provider order, and control the native tools available to the agent.
---

A capability gives the agent a stable, Trema-owned tool whose backend an administrator can replace. Capabilities differ from [connectors](/connectors): a connector publishes provider-specific operations, while a capability keeps one tool contract across providers.

Managing capabilities requires the `manage_capabilities` permission, held by owners and admins.

## Configure web search

Web search supports Brave Search and Tavily. Each provider needs its own API key.

1. Open **Settings → Capabilities**.
2. Choose **Configure** beside a search provider.
3. Enter its API key and save.
4. Under **Routing**, select the primary provider and an optional fallback.
5. Save the route.

The first configured provider enables web search automatically. A configured fallback runs only when the primary request fails. It does not merge, rerank, or supplement successful results.

The agent receives one `search_web` tool regardless of provider. The tool accepts a query, an optional result limit up to 20, and an optional day, week, month, or year recency filter. Results use one shape: title, URL, snippet, and an optional publication time.

Replacing a key overwrites its encrypted value. Trema never returns a saved key. Removing a provider deletes its key and removes the provider from the route; removing the final provider disables web search.

## Configure web fetch

Web fetch uses the extraction API of a configured provider. Tavily currently provides web fetch.

1. Open **Settings → Capabilities**.
2. Configure Tavily under **Web search** if it is not configured.
3. Under **Web fetch**, turn on the route.
4. Select Tavily as the primary provider.
5. Save the route.

The agent receives the `fetch_url` tool while the route is enabled. Tavily Extract returns the page as Markdown. Trema limits the result to 50,000 characters.

One provider record can serve several capabilities. For example, one Tavily API key can appear in both the web search and web fetch routes.

## Disable a capability

Turn off its route and save. The tool disappears from new model turns and external MCP tool listings. Its provider configuration stays available for later use.

## Configure through the API

Drivers describe the adapters bundled with the deployment and list every capability they support. Providers hold an adapter's settings and encrypted credential. Routes enable a capability and list its providers in resolution order.

| Operation | Route |
| --- | --- |
| List bundled drivers | `GET /capability-drivers` |
| List configured providers | `GET /capability-providers` |
| Create or replace a provider | `PUT /capability-providers/{name}` |
| Delete a provider | `DELETE /capability-providers/{name}` |
| List enabled routes | `GET /capability-routes` |
| Set or disable a route | `PUT /capability-routes/{capabilityKey}` |

Set a route's `chain` to an empty array to disable it. Provider names in a route are ordered from primary to fallback and must serve that route's capability.

See the [API reference](/api) for request and response schemas.
