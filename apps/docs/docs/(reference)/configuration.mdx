title: Configuration
description: Every environment variable the Trema server reads, with types, defaults, and behavior.

The server validates its environment at startup and refuses to start on an invalid value, naming the failing variable. Variables come from the process environment and from `apps/server/.env`.

## Core

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `DATABASE_URL` | Yes | — | PostgreSQL connection URL. |
| `HOST` | No | `127.0.0.1` | Address the server binds. Set `0.0.0.0` in a container. |
| `PORT` | No | `3000` | Port the server listens on. |
| `NODE_ENV` | No | `development` | One of `development`, `test`, or `production`. |
| `TREMA_MODE` | No | `dedicated` | Deployment mode: `dedicated` runs a single organization created through the [bootstrap flow](/first-boot), while `hosted` leaves organization creation open to any signed-in account. |
| `HATCHET_CLIENT_TOKEN` | No | unset | Token for the Hatchet workflow engine that executes [runs](/durable-runs). When unset, the server starts, warns that run scheduling is off, and the runs endpoints report the feature unavailable. |

## Logging

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `TREMA_LOG_FORMAT` | No | `logfmt` | Output format: `logfmt` or `json`. |
| `TREMA_LOG_LEVEL` | No | `info` | Lowest level that is written: `debug`, `info`, `warn`, `error`, or `silent`. The `silent` level writes nothing. |

The server writes one record per line to stderr. These settings cover the running server; the other [host commands](/cli) report in plain text instead.

Every record carries `time`, `level`, and `msg`, then the details of that event. Records emitted while handling a request also carry `requestId`, `method`, `path`, and—once resolved—`procedure`, `orgId`, and `principalId`, so one request's lines can be collected from anywhere in the stack. In `logfmt`, nested details flatten onto dotted keys:

```
time=2026-07-24T10:00:00.000Z level=info msg="Server listening" url=http://127.0.0.1:3000
time=2026-07-24T10:00:12.408Z level=info msg="Request handled" requestId=6f5b0c1e-9d21-4f7a-8f0c-2b1d7c3a5e88 method=POST path=/rpc/items/create status=200 durationMs=37
time=2026-07-24T10:00:19.912Z level=error msg="Readiness check failed" error.name=Error error.message="connection refused"
```

In `json`, they stay nested:

```json
{"time":"2026-07-24T10:00:00.000Z","level":"info","msg":"Server listening","url":"http://127.0.0.1:3000"}
```

Use `json` where a log shipper parses the stream, and `logfmt` when a person reads it.

## Authentication

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `TREMA_AUTH_SECRET` | Yes | — | Signs sessions. At least 32 characters; generate with `openssl rand -base64 33`. |
| `TREMA_AUTH_BASE_URL` | No | `http://127.0.0.1:3000` | Public base URL of the server. OAuth callback URLs derive from it. |
| `TREMA_PASSWORD_AUTH_ENABLED` | No | `true` | Sign-in with email and password. |
| `TREMA_OPEN_SIGNUP` | No | `false` | Accept account creation without an invite. A dedicated deployment closes account creation once its first organization exists; set this to `true` to reopen it. Hosted mode ignores it—signup is always open there. |
| `TREMA_GOOGLE_CLIENT_ID` | No | unset | Google OAuth client ID. Set together with the secret. |
| `TREMA_GOOGLE_CLIENT_SECRET` | No | unset | Google OAuth client secret. Set together with the ID. |
| `TREMA_BOOTSTRAP_TOKEN` | No | unset | Dedicated mode only: the [first-boot](/first-boot) token. When unset, one is generated at first start and logged once. |

### Google sign-in

Create an OAuth client in the GCP console and register the callback as an authorized redirect URI:

```
<TREMA_AUTH_BASE_URL>/api/auth/callback/google
```

Set both variables; the sign-in screen shows the Google button whenever they are configured. Setting only one of the pair fails validation at startup.

### Disabling password sign-in

Set `TREMA_PASSWORD_AUTH_ENABLED=false` to remove the email-and-password form. Configure another sign-in method first—with every method off, nobody can sign in.

### Account creation

A dedicated deployment accepts open account creation only until its first organization exists, so the operator can create an account and redeem the [bootstrap token](/first-boot). Afterwards a sign-up needs the token of a pending [invite](/members-and-invites), and one without is refused. Set `TREMA_OPEN_SIGNUP=true` to accept sign-ups without an invite again.

## Connectors

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `TREMA_CREDENTIAL_MASTER_KEY` | Dedicated mode | unset | Base64-encoded 32-byte key that encrypts connector credentials and OAuth client secrets at rest. A dedicated deployment refuses to start without it. Generate it with `openssl rand -base64 32`. See [credential security](/credential-security). |
| `TREMA_INGRESS_DRAIN_TIMEOUT_MS` | No | `30000` | Maximum shutdown wait, in milliseconds, for acknowledged webhook deliveries to commit. |

Configure the Slack signing secret with the Slack OAuth app in **Settings → Messaging**. Trema encrypts it with `TREMA_CREDENTIAL_MASTER_KEY` and never returns it through the API.

## Search

Item search always matches text. An organization whose `embed` model role names a model also gets meaning-based matches beside the text ones. Those find an item that answers the question in different words.

No environment variable turns this on. The embedding model belongs to the organization's model provider registry, assigned in the web app or through the API—see [Model providers](/model-providers).

Each vector records the model that produced it. Search compares only the vectors from the model the `embed` role currently names, so changing the assignment hides old vectors rather than mixing them. Run `POST /api/v1/items/reindex` afterwards to embed everything again. To see which model the stored vectors came from, and how many items still lack a vector from the current one, call `GET /api/v1/items/index-status`. An organization with no `embed` assignment searches text only, and nothing fails because of it.

## Web app

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `TREMA_WEB_ORIGINS` | No | `http://127.0.0.1:5173` | Comma-separated origins allowed to call the API from a browser. The first origin is also where [invite links](/members-and-invites) point. |
| `TREMA_WEB_DIST` | No | unset | Path to the web app's static build, relative to the server's working directory. When set, the server serves it with a single-page-app fallback. |
| `TREMA_TERMS_URL` | No | unset | Terms-of-service link shown in the sign-in footer. Hidden when unset. |
| `TREMA_PRIVACY_URL` | No | unset | Privacy-policy link shown in the sign-in footer. Hidden when unset. |
